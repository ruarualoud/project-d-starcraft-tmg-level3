### 1. 轻量准备和可观测执行

把环境资格核验/准备、等待执行资源、真实角色执行、结算和清理分开计时。
缓存只复用同一内容身份下已验证的运行时材料；保持完整源、运行时代码、OS隔离与证据身份，
不通过删除运行时依赖、免验来源或改为假DSH获得加速。

执行时限不再混淆环境准备/队列等待/清理与模型思考；每个阶段仍有独立有界预算。
先用固定实际恢复输入测单/双通道，再测真实生产原组合。必要的文件准备以资源队列控制，
模型通道隔离与可并行能力保留，不把永久串行当成全部并行问题的解决。

通过标准：实际来源绑定不漂移；已付费恢复0新调用；准备和恢复耗时有前后对照；
无超时后偷偷接受、未结算就关闭账本、孤儿子进程或隔离权限扩大。

### 2. 共用故障路由与上下文保全

| 故障类 | 共用处理规则 |
| --- | --- |
| 完整输出的格式差异 | 仅无损规范化；拒绝歧义JSON/重复key，保留原响应与转换证明 |
| 内容错误或缺项 | 基于来源提出字段级问题和修复，保留完整上下文；修后重新审核相关命题 |
| 容量不足或输出截断 | 根据实际合同有界扩容/拆分输出目标；不截掉来源上下文，不重做已完成目标 |
| 本地准备或执行超时 | 返回具体阶段、执行进度与是否发生发送；只恢复受影响阶段 |
| 确定未发送 | 在既定预算/策略内由调度器安排有界新尝试，不由底层暗中重试 |
| 发送结果不确定 | 保留预留和原尝试，隔离该任务；通过上游对账/明确授权路径决定后续，禁止伪装成未发送 |
| 来源/依赖冲突 | 隔离相应版本与依赖，保留旧版展示；不静默兼容错误内容 |

通过标准：同一分类器/恢复入口覆盖种族、对抗和反思；固定故障注入穿过实际调用接口；
历史真实失败样本也通过。未识别故障有明确终止/隔离路径，不承诺兼容任意坏内容。

### 3. 局部续跑与版本依赖

阶段成果以内容、来源、合同及执行证据身份固定。恢复只重建当前任务所需依赖；
代码变化根据实际影响范围使相关成果失效，而不是把全历史工作流作为每次热启动条件。
恢复、来源审核、独立评估、发布是不同状态，缓存命中不继承未证明的策略或规则正确性。
一条任务的传输不确定不得被丢弃，也不应阻断无依赖的另一条任务；实际402仍停止全部开发。

旧统一入口脚本固定历史父f037及190角色/editor切换点，不能直接当作后续S175的新入口合同。
保留旧报告/历史验证，给当前入口使用对应版本和真实依赖的检查；不得手改报告hash。

通过标准：真实重启不重复发送已付费且可恢复请求；受影响节点局部复验；旧版隔离有效；
验证器检查用户可见输出和证据关系，而不是强制某条源码字符串。
