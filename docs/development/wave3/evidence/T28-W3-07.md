## 原因、方案与影响

旧运行时的单位卡、Supply、速度资料只接纳冻结的 26 个单位。新版 Builder 已有 45 个单位，直接让新单位进入旧资料会被拒绝。

新增显式 v2 单位资料构造器，按同一 release 校验 Builder、单位原文与几何。复用原有编制、速度、Supply 计算函数。旧构造器继续使用原锁与原分母。缺底座的 Raven 保留数值资料和明确的几何缺件，不能获得默认底座。

产品入口为 `createOfficialArmyBuilderQueryPortV1` 的可选 `inspectUnitCardSupply`。Host 注入整份当前单位资料，调用者只传单位语义与声明模型数。返回当前模型数对应的基础 Supply、初始编制、速度和底座来源。这里的声明场景没有读取实战房间，也没有证明控制点或移动合法性。

## 验证计划

入口为 `scripts/verify-wave3-unit-characteristics-v2.mjs`，采用实际 Release Resolver、SQLite 发布存储、Builder Query Port 和原有规则内核。

1. 旧版 26 单位资料与已保存真实工厂资料逐字段相等，旧端口接口不变，新数据仍被旧构造器拒绝。
2. 编译全部 45 单位，保留 44 份已知底座和 1 项缺件。篡改、跨来源注入被拒绝。
3. 从产品入口按每个单位各档人数边界查询，独立与 API 原始 squadProfile 比较。检查速度、初始编制、成本、Supply 及查询无写入。
4. 真实 Builder 购买 Siege Tank 后，查询声明损失后的 Supply。记录该后继属于编军与条件查询。
5. 新进程重开发布存储和产品端口，恢复同一绑定及相同购买、查询结果。

每步保存独立后继。失败后只修对应缺口，保留通过前缀。此门未覆盖战场菜单、原子 Apply、模式、变形、模板或 UI 渲染。
