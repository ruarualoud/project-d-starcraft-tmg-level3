## 双人网页发现的问题

| 用户行为 | 原因 | 修正 |
|---|---|---|
| 导出军表再导入 | 导出写 `+upg:`，导入只识别中文前缀；蝎子的两项升级被丢弃 | 导入识别两种前缀，并核对实际保存的升级名称 |
| 在网页军表页点击导入 | 右下角副官浮窗挡住按钮 | 军表操作行移到列表上方 |
| 使用独立的本机测试配置开房 | 原启动命令依赖旧实验的私有配置，相对的静态文件路径也会导致页面无法打开 | 候选从 Wave3 开局配置读取地图，将前端目录解析成绝对路径 |
| 虫族部署蝎子，接着结束激活 | 生成动作时只检查了当前激活的单位，漏查请求动作的席位；旧房的第 4 个动作实际由对方签下 | 2.99.12 依据请求席位和激活窗口的归属生成结束动作 |
| 虫族席位打开行动页 | “黑暗蜂群”原生动作提供坐标参数，但公共动作缺少网页合同要求的 `constraints` 对象，网页因此拒绝整份菜单 | 2.99.12 在公共动作计算身份前补齐标准字段。实际坐标、占位、距离和视线仍由原生能力复核 |

可在原房回执中核对前三步的行动人和第四步的错签。原记录另存，读取修前房间后继时其状态哈希一致。[修前房间记录](../../../../build/ticket-28-wave3-web-human-staging/qa/pre-seat-fix.public.json) · [原房恢复对照](../../../../build/ticket-28-wave3-web-human-staging/qa/pre-seat-fix-head.public.json)

## 2.99.12 网页验收结果

Standard 采用 2000 分规模，双方使用手动导入的达拉姆（Daelaam）与扎加拉军表。房主在网页生成邀请，第二位玩家从显示的一次性链接入席。房主在网页处理首轮任务，房间签下先手选择，虫族部署蝎子。第 3 次修订时，房主没有结束蝎子激活的动作，虫族的菜单中则有且只有一个结束该单位激活的动作。虫族玩家在网页预览并确认，房间到达 r4，行动权交回玩家一。刷新后两席的棋位哈希相同，双方棋盘均绘出了蝎子。500 分 Skirmish 另用同版规则成功开房。[产品签名与重连记录](../../../../build/ticket-28-wave3-web-human-staging/qa/release-2.99.12/result.public.json) · [虫族行动菜单](../../../../build/ticket-28-wave3-web-human-staging/qa/release-2.99.12/guest-menu.public.json) · [玩家一棋盘](../../../../build/ticket-28-wave3-web-human-staging/qa/release-2.99.12/player1-table.png) · [玩家二棋盘](../../../../build/ticket-28-wave3-web-human-staging/qa/release-2.99.12/player2-table.png)

本次直接操作到首轮交权。两个规模的任务结算、终局显示和窄屏验证沿用既有回执。[原网页验收范围](T28-W3-15.md)

## 测试入口

当前机器从大厅选择双人模式和 Wave3 规模，选择或编辑两份军表后开房。在“房间与规则”中生成一次性邀请，用同一台电脑的另一个浏览器用户或无痕窗口打开。邀请和席位恢复凭证仅供相应玩家持有。本机部署启动命令如下，工作目录为活动工作树。

```sh
node scripts/serve-starcraft-product-v1.mjs --offline --wave3-match-candidate=2.99.12 --port=49979 --data-directory=build/ticket-28-wave3-web-human-staging/host --web-root=build/ticket-28-wave3-web-human-staging/web
```

本次范围为本机 Web 人人对战。异地联机部署还需要独立的可访问 HTTPS 域名、与之匹配的邀请配置及外部访问验收。M25 原生设备、单位媒体补齐、副官实答、人机／机机、策略效果与默认发布分别跟踪。
