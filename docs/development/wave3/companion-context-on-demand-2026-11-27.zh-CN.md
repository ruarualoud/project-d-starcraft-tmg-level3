# 副官按需上下文与玩家自行试聊

范围：本测试分支、Wave3 2.99.12、5483。用户要求先优化上下文，然后自己聊天；随后明确普通聊天不应携带战局，仅在明确问到时提供所需内容。本轮不代用户发送真实模型请求。

## 原因与改变

原来的记忆 `contextTokenBudget` 只约束世界书／记忆拼装，并未约束随后附加的房间数据和完整历史。本场离线重建的一份房间上下文为 726211 字节：地形表约 362 KB、单位原始运行资料约 114 KB、工作台约 119 KB，另有重复军表、升级资料和谱系信息。三次真实试聊的约 24.3 万输入 token 与这种整包注入相符；本轮测量字节数，不把它换算成未经模型回执验证的 token 数。

现在由当前用户消息做本地确定性路由：

| 问题 | 附加的房间内容 | 本场离线测量 |
|---|---|---:|
| 普通闲聊、记住口令 | 仅席位／房间修订和“不提供战局”的说明；不读取作战工作台 | 549 字节 |
| 看下我的军表 | 公开势力／战术卡、编成、升级和资源预算 | 10184 字节 |
| 我的坦克射程是多少 | 坦克资料与当前状态，排除其他单位资料 | 3914 字节 |
| 我还剩多少人口 | 人口／资源相关公开数据 | 7389 字节 |
| 这场任务怎么计分 | 当前任务、计分和任务标记 | 5767 字节 |
| 地形与视线 | 地形属性、明确标注的外接范围、当前模型位置；不冒充精确合法性 | 23295 字节 |
| 规则是否合法 | 当前房间规则快查与动作上下文，缺少的规则仍为未知 | 2714 字节 |

这些数字仅指房间附加内容，不是整个请求：角色设定、触发的世界书／已批准记忆和近期对话仍单独存在。上一条问战局不会让下一条闲聊继续携带战局。识别不到明确需求时不发送整包，而由副官询问所需信息。

房间完整压缩投影仍可用于明确的组合查询，本场约 63.3 KB。单位模型按共享属性编码；地形另有无损矩形差分游程编码，可逐个单元还原原始 footprint 与 originalFootprint，非矩形及已改变原始几何走原样回退。普通聊天不发送这些单元，地形摘要的外接范围明确不是实际占地，不得据此推导通行、碰撞或视线。

对话历史保留在持久会话中；每次请求仅取最近最多 16 条完整消息／约 16 KiB，最后一条消息不截断。遗漏历史明确告知模型，不伪造摘要或记忆。OpenAI 发送前还有 96 KiB 内部 Provider 请求封包上限，超限在领取请求额度与网络发送前拒绝；不会因本地校验失败消耗试用次数。HTTP 层的字段与转义另有封装开销，这不是精确 token 上限。用量日志新增 `promptBytes` 数字，度量这个内部封包，不写入 prompt 正文或任何凭据。

## 额度与界面

用户以为副官关闭时，实际为上一轮三次上限已用完，后发的一条用户消息已保存并等待回复。另一个未使用的角色会话控制台显示“未连接”，进一步造成误解。本房现在直接默认展开「和副官聊天」，显示真实 Key 状态和剩余次数，隐藏这条房间未使用的另一套接通入口。中断提示明确说明额度用完或消息等待回复。

本轮沿用小额试用范围，为用户自己新增三次：服务启动用 `--companion-max-dispatches=6` 表示累计上限，保留原有三次 dispatch，不改变 profile hash、不删除旧日志、不通过换 Key 或重启重置。请求只在用户点击发送或继续时发生。助手不点击继续，也不消耗新额度。

服务更新会清空仅在运行内存中的 API Key；用户需在原密码框重新输入。原房间、双方军表、棋盘和已接受聊天历史保留；不读取或复制真实 Key，不把它写入代码、报告或磁盘。未回复的消息不会在重启后自动继续。

余额没有接入本房应用，现有连接器也未提供组织余额读取能力。公开模型 usage 回执只记录耗用，不能作为组织赠金余额。用户应选择领取赠金的组织，在 [Billing／Credit grants](https://platform.openai.com/settings/organization/billing/credit-grants) 查赠金额度及有效期，在 [Usage](https://platform.openai.com/usage) 查消耗；赠金组织归属与到期规则见 [OpenAI 官方说明](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)。
