# 基础 Skill 生产后的待评审问题

来源：用户 2026-09-09 的追加要求。状态：仅记录，尚未调研、选型或实现。

执行顺序不变：先完成总规则、Terran、Zerg、Terran→Zerg、Zerg→Terran 五件套基础生产及其既定验收，再考虑以下问题。它们不是当前 T18/S174 生成入口的新阻塞条件，不将“问题已记录”计作功能完成。

评审触发点是基础五件套产出及其来源/质量检查完成后，不是等待全部人机、自博弈、复盘升级或长任务结案后；届时再评估这些问题对后续 Harness 与优化切片的影响。当前不为此增加生成前置条件。

## 1. 可控复盘与 Skill 优化

- 是否提供控制台手动触发 Skill 优化，如何选择待优化版本和输入对局？
- 是否可以合并多局结果复盘，而非只对单局失误修改？
- 是否可以停在某个动作，使用搜索算法继续假设操作、比较后续结果、总结并修改计划？
- 用户期待：这种推演与修订计划能力使 Agent 更像人类选手，而不是每步独立给出一个答案。

关联现有范围：T18/S177 复盘与反思、S178 升级回归；是否需要控制台或对战暂停的额外切片，留待评审后决定。

## 2. 数据与主要规则变化后的增量维护

- 数据、主要规则改变时，如何识别受影响的 Skill 内容及依赖？
- 如何保留仍有效的内容，只更新必要部分，避免全量重新生成？
- 如何验证更新、展示旧版并保留可回退的历史？

记录本问题不授权刷新当前冻结数据。实际增量更新方案、粒度和触发方式尚未选定。

## 3. 对战 Agent 的推演工具与多模态规划

- 是否把“假设动作 → 计算/搜索 → 修改计划”作为对战 Agent 的显式能力？
- MCP 应提供哪些数学、概率与桌面位置关系查询？
- 如何保证 Agent 理解真实棋盘、棋子尺寸与位置关系，以及卡位、威胁范围和火力圈交换对局势的影响？
- 在原有纯语言模型方案基础上，多模态输入是否能改善空间理解与策略规划？研究时须核验所用模型/API 的真实视觉输入支持，当前 4.1 文本 canary 不证明多模态能力。

关联现有范围：T18/S176 空间 Harness 与既有空间能力验收、Ticket20 人机与自博弈系列。先比较方案，不预先决定视觉输入、搜索算法、工具合同或产品交互。

评审时继续遵守既有边界：假设与策略不是已发生的真实对局记录；新候选不能跳过来源、独立评估与回归而自动替换已接受 Skill，规则裁定和训练真值权限不因本备忘录改变。
