## 标准化规则：哪些不能混成一次修复

| 类别 | 权威输入/结果 | 允许处理 | 不允许处理 |
|---|---|---|---|
| 输出格式/选定命令错误 | 原始 Provider 回复、选定命令 schema、具体字段诊断 | 在原命令合同内纠正；精确冗余封装可规范化并记账 | 自动创造战略、悄悄丢弃冲突字段 |
| 工具参数错误 | 原查询、原生 queryRepair、失败字段位置 | 仅修参数或查询前提；新的工具结果单独保存 | 把错误查询当成已回答的策略问题 |
| 工具执行异常 | 请求和子操作身份、执行诊断 | 保存已成功子操作；恢复未完成项 | 成功兄弟结果随一处失败丢失、整批重跑 |
| Provider 结果不确定 | dispatch 状态、已保存回复和费用状态 | 先找原回复；无法确认则保持不确定，受控处理 | 当成 JSON 错误自动重复付费 |
| 引用/来源失效 | 原始来源、当前来源、具体引用 | 明确重新绑定已有同源事实；必要时重算受影响只读查询 | 宣称不同来源等价、重签旧真值或静默改历史 |
| 战略质疑 | 模型主张、规则事实、假设及反例 | 模型保留或修订军表/Plan，并解释取舍 | 程序替模型选择某单位、把未知风险改成必胜/不可行 |

统一结果不是把所有对象压成一个 `ok/error`。原生结果和原始字段必须保留；外层只统一身份、阶段、执行状态和纠错责任。当前失败与历史证据分开，历史失败不能自动成为新的当前任务。

## 本轮已落代码的三项修复

### 1. v310：同一地图引用在三个写入命令中的处理不一致

B r21–r23 的原付费 `revise_plan` 携带了一个未识别地图引用。现有 `finish` 能绑定当前军表/地图已有的真实路线证据，`propose/revise_plan` 却将引用静默改为 null，随后又把结果判成“Plan 没有变化”。

修复：三个命令共用当前军表、冻结地图、已认证 route 的绑定规则。保留模型原引用及 `inputAdjustments`，明确工程更改字段和来源。没有匹配证据仍不伪造事实，也不将进场声明升格为合法。无变化诊断也保留转换原因。

证据：`plan-map-binding-v310-red.log` / `plan-map-binding-v310-green.log`。使用 B 原付费回复走真实 model port→session，0 Provider、0 Native；战略文本和原生产 session 不变。已通过，不重跑。

### 2. v311：当前写入失败被旧成功查询盖住

B 请求165约2MB，上方显示旧 r20 成功查询，r21/r22 的真正失败埋在累计历史里。修复后新合同18先呈现精确 requestKey/receipt 对应的一个当前失败，历史成功结果明确标为“已经完成的证据”。旧付费合同17不变；仅无 pendingDecision 的边界升级，不清计数。

证据：`current-operation-feedback-v311-red.log` / `current-operation-feedback-v311-green.log`。原B165具体输入，当前失败一条，历史/原结果不变，0 Provider/Native。已通过，不重跑。

### 3. v313：并行批次一项失败，成功结果丢失

真实 session 原先用 `Promise.all` 后统一入 observations。一项执行异常使该批次提前退出，兄弟查询已成功但未持久化；重启恢复原付费决定后，成功查询也再次执行。

修复：新增 `roster-query-batch-checkpoint-v1`，每个子查询独立 pending/running/completed/failed，保存完整结果与每次执行诊断。全部兄弟结算后再释放 Run；重启只处理未完成项。文件存储的 `query-batches` 独立小记录避免每个子查询重写100MB Teach 历史。结果尚未整批交付时，不修改付费请求的 observations/context；按原顺序一次交付，成功查询不重发。当前失败清除后，历史诊断仍保留。

证据：`query-batch-recovery-v313-red.log` / `query-batch-recovery-v313-green.log`。真实 session＋文件存储，注入工具故障；修复前成功查询调用2次，修复后1次，失败项重试后共2次，决定只生成1次、恢复1次。另检查错输入不串用 checkpoint、缺回执与真实 unknown 分开、unknown 原样保留。0 Provider/Native。这是故障注入，不是一次真实模型完整写表成功。

限制：执行后但尚未成功写入磁盘即机器崩溃的结果，不能凭空恢复。这里的未完成查询仍是只读/隔离假设计算；不把本实现扩张为外部写操作的 exactly-once 保证。
