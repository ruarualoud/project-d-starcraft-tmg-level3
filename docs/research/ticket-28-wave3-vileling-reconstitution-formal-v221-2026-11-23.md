# Ticket 28 / W3-09 · Vileling 与 Swarmling 同房重组

冻结源的两张单位记录有同名重组能力。旧的单来源数据和共享生命周期装配分别只接一张。把两个稳定定义交给真实生产编译器会拒绝 Vileling，即使两张记录均来自同一冻结发布。

重组数据增加显式多来源编译。每条由原定义 ID、原单位记录、付款和效果规则确定，跨单位调用拒绝。候选 Match 2.21 显式装配 Vileling 的已选特征、位移、冲锋后继和重组。新重组从战场事实取得菌毯状态。历史单来源输出保持原身份。

- **正式范围**：同一 Standard 军表选中 53 条能力，50 条登记。Vileling 7/7，Swarmling 5/5。整房能力门仍报告 Zagara’s Swarm 的 Instinctive Reaction、Scourge Queen、Zerg Creep 三项待接。保留拦截。
- **原生组件范围**：同一对合法军表，两个分别声明先前伤亡的隔离房，两支单位同时在棋盘上。分别使用各自合法菜单和一张 Biomass 付款卡提交，行动单位从 7 恢复至 9，另一个单位保持 7。后继出现 Move 和结束激活。每房一条签名，重开 SQLite 后逐房原状态完全相同。
- **旧版**：同冻结两份单来源数据摘要保持一致。旧组件 3.96.0 和含 Swarmling 的正式 Standard 2.20.0 描述符逐字段一致。2.21.0 在后者的同一残局仍给出待放置目标的合法域。
- **停点**：Kerrigan 势力依法拒绝专属于 Zagara 的 Vileling。首次原生夹具漏用原有效队形检查入口，替换为此前已用的权威场景检查。实际正式拒绝和夹具停点分别保留。

本次未改变默认正式 Match 版本。组件仍为 145/162，W3-09 仍为 38/40，Ticket28 为 2/16。零模型、发布和策略效果待独立验收。
