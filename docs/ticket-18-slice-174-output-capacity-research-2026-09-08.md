# Skill 生产输出容量核验与分批策略

核验日期：2026-09-08。只查询模型接口资料；没有更新游戏规则、FAQ、单位或卡牌来源。由主 agent 按 research 技能的一手来源要求完成，遵守用户不启用子 agent 的指示。

## 已确认事实

本地 `content/skill-generation/offline-provider-profile-v1.mjs` 将上下文预算设为1,000,000、输出预算设为4096。后者是项目配置，不是当前模型能力上限。

DeepSeek 当前官方模型页列出 V4 Flash 的1M上下文、最大384K输出。8192低于这个公布的最大值，但真实项目的安全出口、输出合同和能力回执仍须分别验证，不能把网页规格当作本项目已完成的8192-token调用证明。[官方模型规格](https://api-docs.deepseek.com/quick_start/pricing/)

Responses API 的 `max_output_tokens` 同时计算可见输出与推理输出；达到上限可返回 `incomplete`，其原因字段可为 `max_output_tokens`。接口支持JSON Schema，但格式合同不证明规则事实或策略正确。[官方 Responses API](https://api-docs.deepseek.com/api/create-response/)

项目原生适配器明确发送 `reasoning.effort=none`，安全出口也校验此字段。实际96运行Zerg失败账单为223,429输入、4096输出、0推理输出，不能把这次截断归因于隐藏推理消耗。失败状态为 `STRUCTURED_PROVIDER_INCOMPLETE`，不存在可验收的完整Teach产物。

## 分开处理容量与幻觉

更大的输出预算解决“完整答案装不下”，不自动解决幻觉；较短答案也可能错。不能只按token总量断言模型是否幻觉。来源覆盖、条件与例外、字段审查的缺陷率、重复/遗漏率和规则执行案例分别验收。

采用任务分档而非所有角色统一4096：Teach及必要的较长正文可用8192上限；小批来源审查保留4096。上限不是目标字数，不要求模型填满。当前已启动的4096合同保持不变；新容量必须另行绑定配置、能力回执和执行策略，历史成功内容不重付、不重算语义接受。

按来源/策略维度拆分输出，保持完整冻结来源、全章当前版本和先前笔记可见。每批有明确输入、输出槽位和依赖；合并时检查集合覆盖、重复、矛盾与跨批约束，不把一批失败丢弃后宣称整个Skill完成。最终Skill不受Teach中间笔记的2000-token写作目标限制。

真实截断后保留计费/失败回执，以显式新容量或更小的语义批次接续；不接受半截JSON，不原样概率重试，不因扩大输出上限自动放宽来源审查。
