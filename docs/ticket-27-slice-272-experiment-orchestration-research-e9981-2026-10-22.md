# S272 实验与 Teach 编排复核：从反复审文转为可执行的条件实验

日期：2026-10-22。Ticket 27 / Slice 272。状态：**研究建议，尚未实施／验证；开发与模型生产继续暂停。**

## 结论

当前问题不只是模型偶发输出错误。实验合同主要是自然语言、审核可以增加新的事实义务、职责交接依赖模型解释、一些工程事实还需要模型逐句证明，这几项组合成了不收敛的反馈循环。

建议保留现有 P0–P6 主线和原生规则工具，收紧中间接口：模型负责选择值得验证的战略问题和最终取舍；工程负责把明确实验编译成工具操作、计算预先声明的指标、判定条件谓词、管理证据与重试。不要再增加一层泛化审核来审核上一层审核。

这不是“取消事实检查”或“强行把未知判成通过”。应当消除必要工程未知；正常的反例、无收益结果、未来对手不确定性，则不能伪装成格式错误反复重试。

### 综合取舍，而非预先采纳用户举例

用户进一步明确：yes/no、原子化等只是讨论方向，应综合调研独立选择方案。对照四种路径，建议选择最后一种：

| 路径 | 判断 |
|---|---|
| 只修漏传、错绑定和字段 | 必须做，但不足以解决逐句审核与不断新增义务；无法独立收敛 |
| 全部改成yes/no、小指标 | 不采用；会丢掉机会成本、协同、多目标取舍与对手适应性，并可能鼓励只优化容易测的指标 |
| 全部交给自由Agent自主查证与审核 | 不采用；灵活但会重现范围扩张、重试叠加和无效重复，状态正确性也没有保障 |
| 共享决策工作区＋分层问题＋可执行局部实验＋模型综合决策 | 推荐；工程对齐是前提，局部事实可判定，整体策略保留模型判断，靠实际产品验证而非解释篇幅验收 |

“原子化”也不能仅理解为把文句切短。下面补查发现，当前代码事实上已经在按句拆审核，恰恰导致放大；需要原子化的是**有明确对象、条件、观测与决策用途的领域问题**。

## 二、逐项回答本轮问题

### 1. 实验设计哪里合理，哪里不合理

合理部分是提出可信备选、查原生火力／路线／资源事实、允许据证据保留原方案，而不是强迫模型改表。问题在于这些要求尚未成为完整可执行合同：

1. **所问指标超出工具能力。** #742 已明确承认工具返回单攻击行，不能证明声明的联合／顺序齐射总损失。应在实验编译阶段发现，不能做完再反复解释。
2. **实验基线与当前决策对象不一致。** #577 指出当前Goliath已有 Ares、Haywire、Scatter，之前仍按“Ares与另外两种互斥替代”设计。#588 又指出旧测量不能作为当前配置的基线。重新核对配置是必要的；让多个角色反复发现同一配置则不必要。
3. **结论粒度混乱。** “某武器在某场景的期望伤亡较大”“这个升级值得预算”“整份军表更强”是三种不同命题。第一项测得，不代表后两项成立；也不该为证明第一项而被迫证明整局胜率。
4. **缺乏稳定的决策价值边界。** 长时间围绕小配装的解释争论，没有稳定地回到“本次结果会改变哪个选表／Plan决定”。研究应优先影响当前决策，而非无限补充知识。

### 2. 为什么纠错这么多

| 类别 | 已观察到的例子 | 应当由谁处理 |
|---|---|---|
| 参数／结构错误 | schema、漏字段、枚举不符 | 工具参数校验；只能无歧义地规范化，其余给局部修复请求 |
| 读取协议往返 | 139条补读后确认；129条只有该标记 | 明确“工具读取→交付→决策”的正常状态，不计作错误；已交付的同版本资料不再要求确认仪式 |
| 真实工程故障 | #660 `captureSceneLayout is not a function`；v848漏投影参与者 | 工程修复与原步骤恢复，不要求模型重复设计、重写回执 |
| 判定含义错误 | `false`被用于“工具未评估”，后来被当作否定证据 | 类型化状态与确定性结果；不能用提示词长期抵消错误字段 |
| 审核范围争议 | 单行收益被要求证明联合齐射／因果／普适策略 | 按预先声明的实验范围裁决；新命题另立任务，不倒灌旧准出 |
| 作者选择 | 是否保留Goliath或某升级 | 战略角色据已知利弊作选择，不转成无限事实补证 |

代码证据：`packages/roster-strategist/roster-workflow-read-role-v1.mjs`约1213–1259行，发现未读引用后会读取并设置 `confirmation_after_evidence_reads`，要求再次提交；通用错误路径随后累计纠错次数。

该安全目的本身合理：不能自动把“读到了来源”当作“原结论正确”。优化是**先交付相关材料，再让模型作本来就需要的决策**，不是省掉必要的阅读或批准模型未核实结论。

### 3. 为什么重复同样的设计

不是所有相似设计都重复：配置、规则或场景真的改变时需要新对照。但当前轨迹也有无效重复：

- #742 已记录某联合指标无法由当前单行工具证明；#748 又回到旧升级比较。已有工作区、问题分类和工具结果复用，但没有在这次实际交接中稳定保持“当前问题、当前实验、已回答范围、还缺什么”的一致含义；不能说现有系统完全没有状态／缓存。
- #900 审核“战略保留属于解释而非新测量”；#1020 审核“本回复是事实回答而非军表决定”。这些职责／类型信息可由工程表达，没有必要普遍逐句付费审文。
- #1030与#1031的公开理由完全相同，仍引用旧false前提。重新发一个更长纠错请求，不会自动改变其依据。
- `rosterSourceRepairInformationErrorV1`把“现审核认为不足且没有新材料”的回答送回修复；问题是某些失败需要纠正**对旧材料的解释**，并不需要新材料。修复模式没有充分区分“缺事实”与“判读争议”。

建议同问题同条件直接复用观测。文字改写、引用别名、换角色、重新生成工作ID都不是新实验。缺事实走查询；已有事实的误读走有范围的裁决；作者取舍走战略决定。

进一步代码证据：

- `roster-workflow-source-claims-v1.mjs`使用`Intl.Segmenter(..., {granularity:'sentence'})`，把每个非空句段标为assertion并创建来源审核任务；即使句子只是职责说明，也会先产生一项模型审核。若引用了含abilities的来源，还会创建逐能力对照任务。这是可见的调用放大机制，不全是模型自行多想。
- `roster-workflow-question-routing-v1.mjs`优先派发facts；只有没有事实义务时才直接交还作者。`roster-review-data-questions-v1.mjs`的必要性分类主要由模型给出。只要审核继续把选择问题或解释争议分类成necessary_fact，作者就容易持续等待。
- `roster-experiment-progress-v1.mjs`已经有同输入查询复用和single-flight。应扩展其正确的现有能力并修正语义依赖，而不是再建一套平行缓存或把“已有缓存”误报成“完全没有去重”。

### 4. 第三轮工程问题之前没有发现吗

不是现在才发现，轨迹显示：

- #228 表示采纳已审计的2000分候选，但正式 r3 实际为1490分。
- #235 已明确说“当前1490／2000，缺510，旧2000候选不是当前草稿”。
- #549 才通过 `rosterCandidateSelection`选择已审计候选，并经当前Builder复核提交 r4=2000。

因此可以确认**发现早，修复与战略工作调度未及时收敛**。没有证据据此推断开发者最早在哪一分钟意识到问题。

来源修法应是“选定候选→当前Builder验证→原子提交军表和Plan→读取实际提交回执”，预算等派生字段由回执生成。不能以模型的“我已采用2000”当作实际完成，也不该让所有下游角色再发现一次相同缺口。

### 5. 是否改为 yes/no 假设和确定性结论

同意核心方向：**对可计算命题，程序根据事先确定的条件和指标判定，不让模型事后改标准。** 但有两个边界：

- yes/no必须带适用条件与评价量。比如“冻结场景S、指定攻击动作、只切换某升级，目标的期望损失是否增加”，而不是“Goliath是否更好”。
- 骰子概率、抽样估计、路径求解覆盖不足不能强行二值化。精确期望可以计算确定的比较结果，但不是必然实战结果；抽样区间无法区分时可判证据不足；启发式没找到路径不能判不存在路径。

分开两个字段，而不是一个真假混用：

| 维度 | 状态 | 含义 |
|---|---|---|
| 执行 | completed / invalid_input / unsupported / transient_failure | 工具有没有在约定条件下成功完成 |
| 试验判定（仅completed时） | supports / refutes / inconclusive | 观测是否满足预先声明的谓词；不等于战略准出 |

不支持所需指标应在编译时返回明确能力缺口，不能执行一堆低层查询后仍让模型猜答案。必要工程缺口仍须解决；不能静默删掉必要问题“过关”。

### 6. 应沉淀什么经验

应保存“**在条件C下，单位组合U采用动作序列A，相比B，对指标M有什么效果**”，而不是大段自我证明。这与用户要求一致。

建议经验记录包括：场景和参与者、地图拓扑／位置条件、单位规模／伤亡／升级、时机／可用动作／资源、对手响应分支、比较动作、实测或估计指标及方法、适用边界、反例、规则／地图／配置依赖、关联Plan决定、原生回执引用。

战斗中先用同一规则／几何工具检查条件是否满足，再决定引用、重新测量或拒绝套用。模拟场景经验不能冒充真实本局历史；未覆盖的对手响应不能被写成必胜。实验经验可成为既定WikiSkill/EvoTest后续评估的输入，但本轮未评估这两种方法，也不宣称已接入。

## 四、建议的统一设计

### 4.1 保留战略角色，减少模型搬运工作

先按问题性质分层，而非强迫每件事都变成实验：

1. **事实／可行性层**：军表合法性、真实Supply、支付、路径和控点条件。使用统一权威查询，返回有范围的事实或明确错误；不必再提出一个战略假设。
2. **受控比较层**：某场景中两个行动／组合的收益、损失与响应。使用明确对照和可执行指标；效果可以是连续值、概率分布或多个指标，不必只剩一个yes/no。
3. **战略综合层**：如何获胜、优先保谁、预算投哪里、敌人改变计划怎么办。由模型结合Skill和上述证据权衡，输出公开理由和条件Plan；不宣称程序算出了唯一最优战略。

优先修完整输入链：权威数据→当前军表和Plan→角色可见视图→工具实际入参→原生结果→指标→实际提交。每个边界有唯一字段所有者、实际版本／对象绑定和可追踪回执；输入合法不等于调用成功，调用成功不等于候选已提交，提交成功不等于策略更好。

保留总体战略作者与局部Teach的不同职责；实验设计可作为专门的模型步骤，但不再负责重复抄回执、校验数字、证明自己属于哪个角色。

处理顺序：Skill与当前状态 → 战略问题／可信替代 → Teach质疑关键假设 → 工程编译实验 → 原生执行与指标判定 → 作者取舍 → 军表／Plan联合提交 → 仅复核受影响主张 → 条件经验候选。

- 作者决定目标、军表用途、风险收益取舍及是否采纳。A固定军表不能改表，但可用相同实验能力改Plan；B可以联合改表和Plan。
- Teach必须指出具体决策、依据、可能推翻它的观察，以及结果对选择的影响。单纯要求“再证明得更充分”不能无限生成阻塞义务。
- 工程执行器负责依赖、恢复、来源、度量和状态；不能擅自选择单位、编队或用硬编码权重替模型做战略。
- 最终语义审核聚焦重要未覆盖的战略主张。数字相等、来源类型、引用绑定、字段存在等不再逐句调用模型证明。

每个模型提出的阻塞问题应绑定一个当前已采用的Plan主张或必须完成的实验指标，并说明缺失事实如何使该主张不可执行／结论不成立。工程能检查引用、数据类型和依赖，语义必要性由限定范围的Teach／作者解释；发现真正High仍修复，不能为省调用掩盖错误。非关键探索建议另记，不自动变成当前发布门。

场景选择同样属于设计：先从Skill、对手能力、任务与地图识别可能改变选择的情形，再选择代表性场景与不利反制。不能只挑对当前方案有利的靶子；也不能让程序私设收益权重替代模型偏好。若只测一个场景，结论就只在该场景成立。

### 4.2 把文本合同升级为可执行实验规格

现有 `roster-hypothesis-test-v1.mjs`的 `claim/alternative/supportsIf/refutesIf/decisionIf*`都是文本，`controlledConditions/changedFactors`是字符串数组；校验主要检查形状和非空。应保留这些公开解释，但另有可执行部分：

| 字段 | 内容及责任 |
|---|---|
| decisionRef / planClauseRefs | 模型选择要影响的真实决定；服务端绑定当前版本 |
| scenarioRef / participants / context | 已保存或明确构造的局部场景、单位与状态；不允许隐式扩大为整场模拟 |
| alternatives | 明确A/B配置或动作；对手分支固定或分层比较 |
| controlledInputs / interventions | 来自工具输入模型的可寻址条件与允许变化；派生预算/句柄变化不误判为独立干扰因素 |
| metric | 从工具支持列表选指标，带单位、作用对象、时间终点、聚合方式；单行和顺序齐射严格区分 |
| predicate | 操作符、方向、事前阈值／容差及反驳条件；不是一段自由文本 |
| method | 精确枚举、估计或局部原生执行；抽样时记录种子／样本数／不确定性 |
| decisionBranches | 支持／反驳／不足分别影响哪个选择；不强迫模型采纳某一策略 |
| stop / dependencies | 本地实验终点、前置工具能力、证据依赖；由调度器执行 |

服务端生成回执和来源绑定，模型只能引用真实句柄，不能填写“执行成功”“规则批准”“已读”等证明字段。军表和Plan的正式提交版本、成本、单位数量来自实际Builder回执。

### 4.3 一个当前问题的拆分示例

不要问：“Ares配装是不是最好、值不值得、能否赢下整局？”

拆为三个不同层级的问题：

1. **局部效果**：冻结场景S、指定Goliath与目标、指定合法攻击，只改变Ares有／无，比较该攻击的期望损失。程序输出两个值、差值和谓词结果。对当前记录可先复用观测，不为了演示重新调用。
2. **机会成本**：如果要说“值得预算”，比较同预算的完整备选用途。去掉升级留下未花矿，只能测升级边际作用，不能证明它优于把矿花在别处。
3. **实际战术**：如果作者要据此“先射击再抢点”，就定义明确局部动作与对手反制，测损失后的Supply、是否能进控制范围等。工具不支持联合序列时补能力，不把单枪伤害相加冒充齐射或胜率。

“原子化”是一个结论有清晰谓词与范围，不是禁止多单位协同。Medic支援、两队交叉火力、牺牲一队保另一队占点，都可以作为一个明确局部场景，分别测目标收益与风险边界。

### 4.4 冻结当前准出，而不是禁止发现新问题

实验开始前固定目标指标、控制条件、观察终点和必要约束。审核只检查当前承诺。新发现只有在证据表明会使当前结论不成立／误导实际执行时，才能标记当前结果失效并明确依赖；其他优化建议进入下一决策任务。

不能事后为了通过降低阈值，也不能无理由提高准出要求。Teach框架本身可通过后续复盘提出新版本，但不得在同一次审核中悄悄改变标准。

### 4.5 分类型恢复与有限进展

- **传输异常**：网络层恢复；不让模型重写战略，保留请求与费用状态。
- **可确定的参数填充**：当前版本、来源、工具结果绑定由工程填充；字段别名只在唯一等价时规范化，记录转换。不能猜单位、目标、位置或行动意图。
- **真正有歧义的参数**：只返回该工具的错误路径、当前值、预期和可选项；局部修复，不带完整历史重写全Plan。
- **引用未交付**：收齐当前决策的必需证据，再交给模型决定；新材料改变判断时仍需模型消费。读取是正常步骤，不再混称失败。
- **已有事实的解释错误**：进入明确的interpretation-repair，而非强迫寻找新观测；修复器不能靠改写得到“新增证据”。
- **工具未实现／错误方法**：工程能力缺口，不能同参数反复请求模型。必要缺口阻塞对应决定，其他独立准备工作可继续。
- **假设被推翻／无优势**：正常结果，交战略角色采纳替代或说明保留，不记纠错。
- **相同问题＋相同语义条件＋相同观测**：复用，不执行新实验。若继续研究，须声明改变了哪项条件、预计新增信息如何影响选择；这是可检查的进展，不是硬固定三轮战略探索。

异常纠错仍遵守用户的收敛限制；新设计的动态战略研究不能用来绕开同一故障三轮后停的要求。

### 4.6 条件经验的消费和保鲜

保存结构化“条件→行动／对照→指标→适用范围→失效条件”，保留负结果和反例。模型可以解释偏好，不能改测量。实际对局调用同一查询核验条件，不靠相似文案自动套用。

规则、单位、地图或指标实现更新后，按依赖标记需要重验的经验；仅文案变化不使全部实验失效。条件未满足时记录为不适用，不用新措辞伪装成经验有效。发布的Skill、条件实验候选、真实对局记忆继续隔离。

| 原子项目 | 本次应补强的交付物 | 用已有失败证明什么 |

| P3 | 实验编译器、原生执行、指标判定 | 单行不能冒充齐射；缺方法在执行前被发现；同条件可配对，状态变化可定点失效 |

| P6 | 完整产品新鲜运行与中文报告 | 无人工补字段完成军表＋Plan；每个实验能追踪到实际决定和条件经验，再进入原定对局实验 |

优先复现的具体历史缺陷：#228／#235提交对象不一致；#577配置基线错误；#660适配器方法缺失；#742单行指标与联合指标混用；#900／#1020工程类型被模型审文；#1030／#1031同材料判读循环。

比较指标应同时报告：成功交付率、必要工程未知数、重复实验次数、纯协议确认次数、模型调用／Token／耗时、实际修改与保留理由、对照收益及反例覆盖。不能只以请求减少或字段增多宣称策略更好；局部收益不能替代完整对局胜率。具体节省比例必须实测后给出。

验证时应至少分清两个效果：先修输入／结果对齐，再在同材料上比较编排收敛；否则新旧系统拿到不同证据，无法把改善归因于新编排。固定表与从头写表必须走同一产品接口、不同编辑权限，分别证明会保留有效方案、采纳真实改善、在反例下撤回错误假设。所有这些是待执行验收设计，不是本轮已完成的测试。
