## 四、四项 High 结构问题

### H1：持久化状态机唯一，但调度语义不是唯一

核心状态机 `roster-decision-workflow-v1.mjs` 管持久化、显式命令、版本、新鲜度、执行与提交保护，这部分有价值。问题不是发现了两套数据库写者，而是：

- `roster-decision-workspace-run-v1.mjs` 的 synchronize 决定大量后继、归还、修复和复审。
- `roster-workflow-ownership-v1.mjs` 内所有权解析和优先调度已经使用不同的关系集合。
- `roster-workflow-hypothesis-context-v1.mjs` 又有自己的祖先关系集合。
- completed-method-handoff 与 readiness 分别再判断谁仍负责、什么算活动。

这些集合不必完全相同，因为读取依赖和执行所有权本来不同；问题是目前没有统一的有类型关系模型，新增一种交接必须分别修改多处。v718–720 是实际后果，不是仅凭文件数量猜测。

**改造目标：** 一个工作协调模块拥有任务关系及生命周期解释，其他模块调用其查询接口，不再自定义祖先遍历或终态判定。事实依赖、执行所有权、修复关系、引用关系明确分型。读取某条事实不等于继承该实验责任。

### H2：作者职责被派给事实角色，纠错没有按责任拆分

实际请求将以下两项同时作为必要事实调查：

1. 未采纳的集中路线仍缺移动证明；模型一面说“当前不阻塞”，一面标 necessary_fact。
2. 当前 Plan 三项声明未写；这些必须由计划作者制定，不可能被工具发现。

v721 已给战略决策角色增加作者合同，但局部事实／复审／恢复链仍会继承旧的错误分类。仅给最终作者一句新提示不能消除整条派工链的循环。

**改造目标：** 工单区分 `author_decision`、`fact_query`、`comparison`、`source_review`、`input_repair`。已知的缺失 Plan 字段直接交作者，不让查询工具填写；真正依据不足继续查证。模型需明确解释未采纳备选对当前选择的必要性，不由 Host 任意删问题。

格式修复只修格式；输入修复只修请求；语义矛盾回问题负责人；能力缺失返回可执行的缺口报告。不能把这些都化为同一份完整回复的重复生成。

### H3：父实验被复制为多个子实验，角色实际范围扩大

当前实际请求继承 6 个 hypothesisTest，战略陈述均是“集中部署(3+5)……分兵部署(1+3+5)……”。它们来自：修剩余队形、持点比较、修队形、分兵几何、读动作菜单、应用静态方案等不同工作单。

局部几何和菜单步骤本应只交付自己的事实谓词，却携带了重复父假设；上下文投影沿祖先累积这些设计，校验器再要求受领的测试逐一评估。于是补一个控点测量，会同时卷回多个旧实验评估。

**改造目标：** 父比较有一个稳定 experimentId 和一个版本化设计。子工作只引用 parentExperimentId／armId／需要交付的 predicate，不复制整个假设并重新成为实验负责人。局部工具成功不能自动完成父比较，但也不该被迫重判父假设。

允许 Teach 提出有价值的新策略，不允许它静默扩大原任务。新问题应作为提案交战略负责人，说明决策价值和停止点；不默认升级为全军多回合演练。

### H4：有原件存储，没有同等清晰的“这条观测证明什么”管理

现有 store 已有不可变内容寻址与检查点；完整 stateRef 也已经统一候选和分支身份。**不是要再造文件库或增加签名门禁。**

但固定实验中，场景摆放、动作菜单、控点测量被反复错引。设计附在工具来源上，测量又是另一条来源，模型需要同时维护编号、原件、分支、测试归属和证明范围，才知道应该评估哪一个实验。

**改造目标：** 在现有 store 上统一资产清单：源数据／地图／规则版本；候选军表＋Plan版本；实验设计＋两臂＋终点；场景 stateRef；观测 predicate＋来源＋适用条件；提案／审核／采纳决定。视图只是原件投影，读取状态不是事实批准。

结果应能直接查询“实验X的集中臂在终点T，控点测量是否存在、来源是什么、几何是否有效”，而不是让模型从几十个 receipt 中自行拼接身份。摘要／别名不变成新证据；不把旧源重签为当前真值。

## 五、工具到底能不能支撑角色

| 需要的能力 | 实证状态 | 准确限制 |
|---|---|---|
| 规则／Skill／已有原件读取 | 已有真实成功 | 工具存在不等于本角色实际读到；须以实际请求为准 |
| 写表选择、合法性、预算分支、联合提交 | 已从空表产出 Native legal2000＋Plan | 合法与满分不证明搭配更好 |
| 联合静态底盘／连续性摆放 | 已有真实整组选项与应用 | 单位各自可放不代表合并可放；静态可放不证明行动到达 |
| 条件控点／补给／计分查询 | 已有真实同源返回 | 固定姿态条件控制不等于已授VP，不等于受压后仍能守住 |
| 局部 Native 行动及火力查询 | 已有局部成功证据 | 需动作域、阶段、目标和资源前提；零合法攻击不是零伤害能力 |
| 路线／到达论证 | 有局部能力与证据 | 尚不能据此宣布当前所有采纳路线均已闭合；也不应要求每张预案都有完整未来历史 |
| 同条件两方案、作用后收益与反制比较 | 尚未完整证明 | 静态占点比较替代不了已声明的受压后比较 |
| 自动计划作者闭环、完整稳定生成 | 未验收 | 当前仍有角色错派与相同纠错重复 |

现在 descriptor 用函数是否存在过滤操作，说明“可以调用”，不是“这个任务的所需谓词一定支持”。应在实验设计后作能力匹配：所需输入、允许副作用、输出谓词与证明范围是否匹配；缺失能力在执行前明确返回，不能执行十几个先决查询后继续扩大目标。

工具结果至少要分开：传输／执行结果、Native规则判定、观测内容与证明范围、后继需要模型选择的事项。采样没找到不能当连续空间无解，参数错不能当规则非法，未知不能当0。

## 六、建议保留的角色与权限

不需要更多泛化 Agent。保留已有分工思想，缩小每个阶段的接口：

| 角色／执行者 | 只负责 | 不应负责 |
|---|---|---|
| 战略负责人 | 军表与Plan联动、目标、假设、取舍、采纳／驳回、必要性争议 | 手写工具回执、制造实测数值 |
| 局部 Teach | 指定策略块的质疑、可信备选、反例、所需比较 | 直接改军表、默认授权新顶层目标 |
| 实验设计阶段 | 把已批准比较转为两臂、控制条件、观测终点和停止点 | 顺便补全整场未来对局 |
| 事实／方法阶段 | 实现指定谓词，选工具、读结果、明确能力缺口 | 给整张军表作最终排名、替计划作者制定声明 |
| 来源／比较审核 | 核对来源、同条件、机制后观测、结论与适用范围 | 因引用了一份旧场景便继承其全部历史实验 |
| 确定性协调与执行代码 | 派工、状态、资产引用、原生调用、恢复与提交 | 战术打分、替模型决定阵型／获胜路线 |

实验设计与方法阶段可以共用底层 Provider Adapter，不必增加新的常驻模型；重点是不同阶段有不同输入、输出权限与返回位置。事实汇总也不必每个机械成功后都强制付费调用，只有确需语义解释时才调用。

局部事实任务应收到：原问题、它负责的谓词、相关条件与精确资产入口、所需工具描述和返回负责人。父目标保留简明目的摘要；完整历史按需读取，不再默认继承所有祖先义务。当前单次请求工具菜单约55,175字符、exact_read_results约286,385字符，说明分块曾有效，但没有贯穿后续深层纠错。

## 七、如何统一，而不是再叠一层包装

建议围绕三个已有深模块收敛，而非另起并行旧／新链：

1. **工作协调模块**：统一所有权图、可运行判断、暂停／归还／完成／替代、幂等提交与恢复。数据库／状态文件还是现有唯一入口。独立只读任务可以并行；同一场景写入及军表Plan提交受控串行。
2. **资产目录模块**：原件与语义清单、版本适用性、视图和实际交付状态、实验两臂与观测对齐。原件只存一次；内容hash只作存储身份／完整性，不充当策略批准，也不因无关Plan改动全量失效。
3. **有类型的任务执行接口**：统一 query／author／compare／review／repair 的输入和结果。工具 Adapter 保留 Native 权威；角色 prompt 由已确定的阶段生成，不靠不断附加提示纠正角色权限。

收敛度不以“又查询一轮”判断，而以义务是否有实质变化判断：新增可用观测、修正设计／方法、明确放弃不相关备选、作者实际制定／修改计划、独立审核解决具体问题。相同问题、相同材料、相同错误输出不能再支付完整重试；应保留原件并回交明确负责人或报告能力缺口。新的有效方法仍可被授权，不能用固定查询次数削弱策略。

这不能保证消除所有模型错误，但能让错误局限在明确角色／步骤，并使可自动恢复的问题不再升级为全流程人工补丁。
